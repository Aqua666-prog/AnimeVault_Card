# AnimeVault Cards — Gameplay UI v2

## Аудит и границы

База изменений: main `234388a`, после #7 (уровни/NP) и #8 (EXP/отряд/башня).
Сохранены aiogram, GameService, SQLAlchemy/asyncpg, PostgreSQL и Alembic.
В main действительно существуют четыре Fate-карточки с PNG, уровни 1–100, NP 1–5,
кошельки с lifetime XP и расходуемым training_xp, слоты отряда и история башни.
Новые персонажи, изображения, внешние API, платежи, HTTP-серверы и Mini App не добавлены.
Railway, секреты и DSN/TLS не изменены. Деплой и merge не выполняются этой работой.

Текущие недостатки: недоступные из меню развитие/награды, профиль без боевой
статистики, коллекция без фильтров, башня только с последним повторным этажом,
отсутствие заданий/достижений/почты и невозможность бесконечного роста врагов
при конечном максимуме силы карточек. Новые разделы используют реальные записи БД.

## Реализованный цикл и навигация

Призыв → экземпляры → отряд → бой → Coins/EXP → развитие → задания/достижения →
награды → следующий призыв. В главном меню сетка по две кнопки: профиль, коллекция,
призыв, отряд, башня, активности, задания, достижения, награды, почта, помощь, календарь.
Новые разделы имеют единый заголовок, разделитель, прогресс и возврат в меню.
Редактируются текст, подпись и медиа существующего сообщения, когда это допускает
Telegram. Для длинного текста после фотографии используется отдельное сообщение,
поскольку подпись ограничена 1024 символами. Callback data остаётся в пределах 64 байт.

Команды: /start /profile /collection /catalog /summon /rates /team /tower /daily
/history /help и новые /quests /weekly /achievements /rewards /mail /calendar
/activities /tutorial. Прежние callback-ссылки сохраняют совместимость.

Профиль показывает ранг аккаунта, lifetime XP и XP до ранга, доступный тренировочный
EXP, Coins, Fate-прогресс, общую и архивную коллекции, сильнейшую карту, рекорд,
победы/поражения, достижения и регистрацию. Ранг = 1 + lifetime XP // 100;
прокачка экземпляров расходует только training_xp.

Коллекция хранит отдельные UUID. Фильтры: все, редкость, персонаж, франшиза, уровень,
NP, избранные, отряд, дубликаты. Сортировки: сила, уровень, редкость, NP, время.
Экземпляр показывает HP/ATK/DEF, силу, уровень, NP, избранное и слот, цену следующего
уровня. Доступны +1, +10 и максимум за EXP, NP-слияние, выбор слота, другие копии.
Избранные, прокачанные и состоящие в отряде материалы по-прежнему не сливаются.
Сила = HP + 5 ATK + 3 DEF, одинаково в коллекции, отряде и профиле.

## Сохранённые экономические формулы

- Бонус нового аккаунта: 1000 Coins, только в транзакции регистрации.
- Fate: 3300/3300/3300/100 базисных пунктов; secrets.randbelow(10000), независимо
  на каждый результат. ×1 = 100, ×10 = 1000; без скидки, pity и гарантии.
- Цена уровня n → n+1: 2n EXP. Полный путь 1 → 100 = 9900 EXP.
- NP 1 → 5: одна чистая копия того же героя за шаг; материал остаётся в истории
  с consumed_at, без удаления. Карточки отряда и избранные защищены.
- HP/ATK/DEF = base × (100+2(level−1)) × (100+15(NP−1)) // 10000.
- База ежедневного бонуса: 300 Coins, день UTC, один раз.

## Башня 2.0 и обоснование нового баланса

Квадратичная кривая прошлой версии имела фактическую стену для конечного отряда
100/NP5. Новая кривая для s = floor−1:

```
HP  = 900 + 50000*s // (s+150)
ATK = 80  +   600*s // (s+150)
DEF = 40  +   500*s // (s+150)
```

Рост плавный, целочисленный и не убывает; нет финального сюжетного этажа.
Сила приближается к достижимому развитым полным отрядом пределу. Типы по floor % 5:
1 — сбалансированный, 2 — защитник (каждый третий удар отряда −10%), 3 — быстрый
атакующий (каждая третья атака +20%), 4 — живучий (восстановление 1% HP раз в три
раунда), 0 — босс (каждая пятая атака +20%). Скрытых скачков статов босса нет.
Отряд атакует первым, до 60 раундов; между боями HP восстанавливается.

Новые награды первого прохождения:

```
Coins = min(400, 80 + 25*floor)
EXP   = min(300, 35 + 15*floor)
```

Повтор даёт половину с округлением вниз. Первые 12 этажей сохраняют монеты,
первые 17 — EXP прежней формулы. Прежние потолки 100000/50000 непригодны после
устранения стены сложности: одна высокая победа мгновенно оплатила бы несколько
максимальных карточек. Новые потолки сдерживают поздний фарм без энергии и ожидания.
Прежние wallet, XP и уже записанные TowerRun.coins/xp не пересчитываются.

Сценарии симуляции (первые три SSR из каталога, одинаковые уровни/NP):

| Игрок | Отряд | Проверенный фарм | Coins / EXP за повтор | Бои для 9900 EXP | При 8 сек на действие |
| --- | --- | --- | --- | --- | --- |
| Новичок | 1× Artoria, 1/NP1 | этаж 7 | 127 / 70 | 142 | 18,9 мин |
| Средний | 3 SSR, 40/NP2 | этаж 100 | 200 / 150 | 66 | 8,8 мин |
| Развитый | 3 SSR, 100/NP5 | этаж 100 | 200 / 150 | 66 | 8,8 мин |

Это расходы с нулевого банка EXP на **одну новую карту**, не время до полного
отряда: три карты требуют 29700 EXP (198 повторов на капе, около 26,4 мин в модели).
Время 8 сек — предположение о действиях человека, а не навязанный таймер: API
не ограничивает скорость боёв, автоматизация может быть быстрее. Оба развитых
профиля получают по два одиночных призыва за повторный бой на капе; у новичка
это один призыв за бой с остатком. Ранние уровни быстрые, поздние требуют накопления.
Базовые первые победы, задания и достижения помогают перейти от одной карты к трём.
Протестированы все пять архетипов на этажах 1000000–1000004 для полных 100/NP5 отрядов
каждого из четырёх персонажей. Это проверка отсутствия арифметической стены, не
заявление о живой нагрузке на Railway. Дальнейший баланс стоит сверять с телеметрией.

За важные этажи дополнительно открываются постоянные награды (Coins / EXP):
5 → 100/100, 10 → 200/200, 25 → 350/350, 50 → 600/600, 100 → 1000/1000.
Их забирают в наградах один раз. Бой хранит снимок врага, отряда, урона и журнала,
поэтому его история не меняется после прокачки. Есть прогноз и предупреждение
о слабом отряде, выбор любого открытого этажа и кнопка повтора.

## Награды и периоды

Общий RewardGrant: UUID, получатель, уникальный ключ, категория, причина, Coins,
EXP, время создания, срок получения и квитанция claimed_at. Получение блокирует
того же игрока, что и призыв/бой, проверяет все лимиты до изменений, начисляет
Coins и оба счётчика опыта и пишет валютный журнал. Claim all атомарен; один отказ
откатывает все квитанции/ресурсы. Повтор UUID даёт нулевое начисление.

Прогресс вычисляется по Summon.count, CardUpgrade.steps, TowerRun и DailyReward,
а не по количеству callbacks. ×10 — десять независимых призывов для целей.
Вход — уникальная PlayerVisit на день UTC. Завершённые дневные/недельные задания
получают ключ даты периода и expires_at. День начинается в 00:00 UTC, неделя —
в понедельник 00:00 UTC. Просроченное задание нельзя получить через старую кнопку;
новый период учитывает только свои подтверждённые действия.

Достижения постоянны. Достоверная история (включая сожжённые копии) учитывается
ретроактивно; старые первые этажи восстанавливаются по полной награде победы,
а не по произвольному повторному бою. Недостоверные события не выдумываются.

Календарь — семь успешных дневных получений, пропуск не обнуляет цикл. Дни 1–6
открывают 20/40/60/80/100/120 EXP; день 7 — 100 Coins и 200 EXP. Потом новый цикл.
Базовые 300 приходят сразу; календарные бонусы отдельно доступны в наградах без
истечения срока. За цикл: 2100 базовых Coins + 100 бонусных, 620 EXP.

Почта поддерживает компенсации, подарки, события и административные выдачи через
одну операторскую команду без Telegram-токена:

```sh
python -m cardlegends.cli gift TELEGRAM_ID UNIQUE_KEY 'Причина подарка' --coins 100 --xp 50
```

Нужен защищённый DATABASE_URL уполномоченной роли. Повтор ключа с тем же содержимым
не создаёт копию; изменение суммы при том же ключе отвергается. В Telegram нет
команды создания подарков или передачи суммы через callback. Письма имеют подробный
просмотр, состояние, историю получения и «Получить всё» только для текущего игрока.

Обучение из восьми шагов отражает реальные действия. Новые игроки могут пропустить
или продолжить его; текущие пользователи при миграции помечены пропустившими, пока
сами не откроют /tutorial. Перезапуск не сбрасывает состояние. Уведомления встроены
в ответ действия и счётчики разделов; фоновых рассылок и спама при старте нет.

## Миграция, права и сохранность

`0006_gameplay_ui_v2` после `0005_tower_squad_training`:

- Расширяет balance/xp/training_xp и валютный журнал до BIGINT, не меняя значений.
- Разрешает до 99 переходов в одном CardUpgrade для MAX без смены UUID карточки.
- Добавляет update ID с уникальностью player/update в DailyReward: повтор после полуночи возвращает старую квитанцию.
- Добавляет nullable report и first_clear в TowerRun, сохраняя исходные поля.
- Создаёт reward_grants (уникальный player/key), player_visits (player/day),
  player_journeys (player), с FK, индексами и серверными значениями по умолчанию.
- Старым игрокам устанавливает только состояние пропущенного обучения.

Переполнения проверяются до начисления, потолок ресурсов — 2^63−1. Новые суммы
не могут быть отрицательными. Деньги, NP, уровни, команды, источники артов, история
призывов, боёв и consumed_at не удаляются и не пересчитываются. Production downgrade
заблокирован: удаление квитанций позволило бы повторные выплаты. Служебный downgrade
для изолированных БД с суффиксом _test нужен регрессионным тестам; он не сужает
BIGINT и не запрещает уже сохранённые шаги MAX.

Runtime-роли нужны дополнительно:

```sql
GRANT SELECT, INSERT, UPDATE ON reward_grants, player_journeys TO bot_role;
GRANT SELECT, INSERT ON player_visits TO bot_role;
```

Сохраняются SELECT/INSERT/UPDATE на players, wallets, owned_cards, render_cache,
card_upgrades, tower_progress, tower_runs; SELECT/INSERT на summons, summon_results,
currency_transactions, daily_rewards; SELECT/INSERT/UPDATE/DELETE на squad_slots.
Каталог — SELECT, а для первого seed также INSERT. Локальный scripts/migrate.py
обновлён для cardlegends_app; на Railway подставляется фактическая роль, без её
создания, расширения до SUPERUSER и изменения паролей. Таблицы мигрирует DDL-роль,
она же выполняет backfill первых этажей и состояния обучения.

Обновление оператором:

1. Проверить PR/CI и создать pg_dump custom backup из защищённой операторской задачи.
   Не печатать DSN/пароли. pg_restore --list и пробное восстановление на отдельной БД.
2. Сохранить текущие Railway variables, DSN/TLS и оригинальные PNG. Проверить
   `python -m cardlegends.cli check-cards` — должно быть 4/4.
3. Остановить предыдущий polling-процесс; не запускать два процесса на один токен.
4. Выполнить `alembic upgrade head` с правами мигратора. Не делать downgrade и не
   удалять volume/БД. Alembic читает DATABASE_URL, не MIGRATION_DATABASE_URL сам.
5. Выдать минимальные runtime-grants, если роли разделены. Запустить одну реплику.
   Прежняя команда `sh -c 'alembic upgrade head && exec python -m cardlegends.main'`
   совместима, если используемая роль имеет права на обе стадии. Dockerfile Railway
   не менялся; отдельный порт и HTTP healthcheck не добавляются.
6. Проверить /start дважды (без повторного бонуса), старую коллекцию/NP/отряд,
   бой и его повторную доставку, дневной бонус, задания, награды, почту, /tutorial.
   После рестарта данные и квитанции должны сохраниться.

## Проверки и ограничения

Автотесты используют отдельную PostgreSQL 16+ с суффиксом _test, реальные миграции
и aiogram Dispatcher с fake Telegram. Проверяются конкуренция и rollback квитанций,
периоды UTC/понедельник, семь дней с пропусками, MAX, NP/отряд/избранное, постоянные
достижения, доступ к чужим наградам, переполнение, сохранность заполненной схемы
0005, совместимость ORM и миграций, callback/HTML/лимиты и редактирование медиа.
Весь прежний регрессионный набор сохранён; изменена только проверка верхнего
потолка наград башни согласно новому балансу. PNG 4/4 проверены локально, исходники
не менялись. Настоящий Telegram API, production нагрузка и deployment на Railway
не проверялись в этой работе. Функциональных заглушек P0/P1/P2 нет; будущие типы
ресурсов и календарные live-события требуют отдельного продукта/контента.
